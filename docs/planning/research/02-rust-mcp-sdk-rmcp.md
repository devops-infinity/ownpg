## 3. Conflicts found and how they were resolved

- "rmcp implements 2026-07-28" versus `ProtocolVersion::LATEST = V_2025_11_25` and an initialize default of 2025-11-25. Resolved from source at tag and PR #1228: 2026-07-28 has no handshake, so `initialize` is legacy-only by design; `KNOWN_VERSIONS` and `supported_protocol_versions()` include 2026-07-28; discovery and per-request `_meta` select the modern era. Both statements are true.
- The dev.to article (rmcp 3.1.2) reports `initialize` returning 2026-07-28; on 3.2.0 and later it returns a legacy version. Resolved by version: behavior changed 2026-08-31 in PR #1228.
- The mcpkit comparison doc lists rmcp transports as "stdio, Streamable HTTP, SSE [legacy], child-process". Resolved against crates.io feature lists and the CHANGELOG: SSE was removed in 0.11.0 and the README calls it a non-goal. The mcpkit claim is discarded.
- ChatForest (March 2026) lists rmcp's license as MIT. Resolved from the registry: Apache-2.0 since 0.13.0 (2026-01-15).
- Conformance counts differ: rust-mcp-sdk says 110/110 and 440/440; the Tier 1 PR cites 67/67 and 50/50 on frozen requirement sets with alpha.11; rmcp's ROADMAP says 30/30 per date-versioned suite; PR #1020 says 35/35 tasks checks. These measure different suites, filters, and suite versions and are not comparable; none contradicts another. Reported as is.
- Conduid says rust-mcp-sdk's last commit was seven months ago; the GitHub API shows a push on 2026-09-11. Resolved in favor of the API; Conduid discarded.
- Stackademic (2026-02-21) says rust-mcp-sdk defaults to 2025-06-18; its 2.0.0 README says 2026-07-28. Resolved by recency and primary source.
- MSRV: rmcp says 1.88; apollo says 1.92; a zavora README says 1.94.1; the dev.to author used 1.97.1; sqlx 0.9.0 declares 1.94.0. Resolved: rmcp's MSRV is 1.88; higher numbers are downstream project choices or come from sqlx.
- `rand`: crates.io reports max stable 0.10.2 but newest-by-date 0.8.8 (a 2026-08-25 backport). Not a conflict; noted so a `latest` lookup is not misread.
- goose docs show `#[async_trait] impl ServerHandler` and `rmcp::Result`; current rmcp uses async fn in trait and `ErrorData`. Resolved by code reality: the docs are stale; the PRs confirm goose uses rmcp.
